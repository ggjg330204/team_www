## ⚠️ 중요: Web VMSS 접속 구조

Web VMSS는 **개별 인스턴스에 Public IP가 없습니다.**  
**Load Balancer의 NAT Pool**을 통해 SSH 접속합니다.

| 구성 요소 | 설명 |
|-----------|------|
| **접속 IP** | Load Balancer Public IP (`www-lb-pip`) |
| **SSH 포트** | `50001` ~ `50010` (NAT Pool 범위) |
| **인스턴스 매핑** | 포트 50001 → 1번 인스턴스, 50002 → 2번 인스턴스 |

## 1. 사전 준비: 변수 설정 및 정보 확인 (로컬 PC)

아래 블록 전체를 **로컬 PC PowerShell**에서 복사해서 실행하세요.

```powershell
# 1. Terraform 상태 갱신
terraform refresh

# 2. 기본 변수 저장
$RG_NAME    = $(terraform output -raw resource_group)
$MYSQL_HOST = $(terraform output -raw mysql_host)
$REDIS_HOST = $(terraform output -raw redis_host)
$FD_HOST    = $(terraform output -raw frontdoor_endpoint_hostname)
$TM_FQDN    = $(terraform output -raw traffic_manager_url) -replace "http://", "" -replace "/", ""
$KV_NAME    = $(terraform output -raw key_vault_name)

# 3. Load Balancer Public IP 및 SSH 포트 조회
$WEB_PUBLIC_IP = az network public-ip show --resource-group $RG_NAME --name "www-lb-pip" --query "ipAddress" --output tsv
$SSH_PORT = az network lb inbound-nat-pool show --resource-group $RG_NAME --lb-name "www-lb" --name "ssh-nat-pool" --query "frontendPortRangeStart" --output tsv

# 3-1. Mail Server Public IP 조회
$MAIL_IP = az network public-ip show --resource-group $RG_NAME --name "mail-pip" --query "ipAddress" --output tsv

# 4. WAS VMSS의 Private IP 확인
$WAS_PRIVATE_IP = az vmss nic list --resource-group $RG_NAME --vmss-name was-vmss --query "[0].ipConfigurations[0].privateIPAddress" --output tsv

# 5. Application Gateway Public IP 조회
$APPGW_IP = az network public-ip show --resource-group $RG_NAME --name "www-appgw-pip" --query "ipAddress" --output tsv

# 6. 설정 확인 (값이 비어있지 않아야 함)
Write-Host "============================================"
Write-Host "리소스 그룹       : $RG_NAME"
Write-Host "Web 접속 IP       : $WEB_PUBLIC_IP"
Write-Host "SSH 시작 포트     : $SSH_PORT"
Write-Host "WAS 내부 IP       : $WAS_PRIVATE_IP"
Write-Host "App Gateway IP    : $APPGW_IP"
Write-Host "MySQL 호스트      : $MYSQL_HOST"
Write-Host "Redis 호스트      : $REDIS_HOST"
Write-Host "Key Vault 이름    : $KV_NAME"
Write-Host "Traffic Manager   : $TM_FQDN"
Write-Host "Front Door        : $FD_HOST"
Write-Host "Mail Server IP    : $MAIL_IP"
Write-Host "============================================"
Write-Host ""
Write-Host "[접속 명령어 예시]"
Write-Host "Web 1번 인스턴스: ssh -p $SSH_PORT www@$WEB_PUBLIC_IP"
Write-Host "Web 2번 인스턴스: ssh -p $([int]$SSH_PORT + 1) www@$WEB_PUBLIC_IP"
```

## 2. 서버 접속 가이드

### 2.1 Web VMSS 접속 (Load Balancer NAT Pool)

Web 서버는 **Load Balancer NAT Pool**을 통해 접속합니다. **반드시 `-p` 옵션으로 포트를 지정**해야 합니다.

> **⚠️ 주의:** Azure Load Balancer는 **4분 Idle Timeout**이 있습니다. `-o ServerAliveInterval=60` 옵션을 추가하세요!

```powershell
# Web 1번 인스턴스 접속 (포트 50001) - Keep-Alive 포함
ssh -o ServerAliveInterval=60 -p $SSH_PORT www@$WEB_PUBLIC_IP

# Web 2번 인스턴스 접속 (포트 50002)
ssh -o ServerAliveInterval=60 -p $([int]$SSH_PORT + 1) www@$WEB_PUBLIC_IP
```

> **💡 Tip:** 각 VMSS 인스턴스는 NAT Pool 포트 범위 내에서 순차적으로 포트가 할당됩니다.  
> 포트 `50001` → 인스턴스 1, 포트 `50002` → 인스턴스 2, ...

---

### 2.2 WAS VMSS 접속 (Private IP) - 3가지 방법

WAS는 Private IP만 있어 외부에서 직접 접속할 수 없습니다. **Web 서버를 경유**해야 합니다.

#### **방법 A: SSH 터널링 (가장 추천 👍)**

Web 서버를 통해 **내 PC의 포트(2222)를 WAS의 포트(22)와 연결**합니다.

1. **터널 생성 (터미널 1)** - 이 창은 켜두세요.
   ```powershell
   # 로컬 2222 포트 -> Web 서버 경유 -> WAS 22 포트
   ssh -o ServerAliveInterval=60 -N -L 2222:$WAS_PRIVATE_IP`:22 -p $SSH_PORT www@$WEB_PUBLIC_IP
   ```
   *(커서가 깜빡거리며 멈춰 있으면 연결 성공입니다)*

2. **접속 (터미널 2)** - 새 창을 열어서 접속합니다.
   ```powershell
   # 내 PC(localhost)의 2222 포트로 접속하면 WAS로 연결됨
   ssh -o ServerAliveInterval=60 -p 2222 www@localhost
   ```

#### **방법 B: ProxyCommand (한 방 접속)**

`-J` 옵션이 안 될 때 사용하는 호환성 높은 경유 접속 명령어입니다.

```powershell
ssh -o ServerAliveInterval=60 -o ProxyCommand="ssh -p $SSH_PORT -W %h:%p www@$WEB_PUBLIC_IP" www@$WAS_PRIVATE_IP
```

#### **방법 C: 수동 2단계 접속 (가장 확실)**

명령어가 복잡할 때 가장 단순하게 접속하는 방법입니다.

1. Web 서버 접속:
   ```powershell
   ssh -o ServerAliveInterval=60 -p $SSH_PORT www@$WEB_PUBLIC_IP
   ```
2. WAS 접속 (Nu Shell 헬퍼 함수 사용):
   ```nu
   was
   ```
   > **💡 참고:** `was` 함수가 자동으로 az cli를 통해 WAS IP를 조회합니다.

### 2.4 Mail Server 접속

메일 서버는 고유한 **공인 IP(mail-pip)**를 가지고 있어 직접 접속이 가능합니다. 단, 보안을 위해 **지정된 IP**에서만 SSH 접속이 허용됩니다.

```powershell
# 1. 접속
ssh -o ServerAliveInterval=60 www@$MAIL_IP
# 비밀번호: It12345!
```

> **💡 메일 계정 알림:**  
> 웹 사이트(`register.php`)에서 회원가입 시 그 계정이 자동으로 메일 서버에도 생성됩니다 (`username@04www.cloud`).

## 3. 데이터베이스 접속 (MySQL / Redis)

### 3.1 MySQL 접속

> **⚠️ 중요:** MySQL은 **WAS 서버**에서 접속해야 합니다. Web 서버에서는 직접 접속이 불가능합니다.

**방법 A: WAS 서버에서 헬퍼 함수 사용 (가장 간편 👍)**
```nu
# WAS 서버 Nu Shell에서 실행
mydb
# 비밀번호: It12345!
```

**방법 B: WAS 서버에서 직접 명령어**
```nu
mysql -h $env.MYSQL_HOST -u www -p
```

**방법 C: 로컬 터널링 (Workbench/DBeaver 사용 시)**

1. **터널 생성 (터미널 1):** 로컬 3307 포트를 MySQL 3306 포트로 연결
   ```powershell
   ssh -o ServerAliveInterval=60 -N -L 3307:$MYSQL_HOST`:3306 -p $SSH_PORT www@$WEB_PUBLIC_IP
   ```
2. **DB 툴 접속 정보:**
   - **Host:** `127.0.0.1` (localhost)
   - **Port:** `3307`
   - **User:** `www`
   - **Password:** `It12345!`

### 3.2 Redis 접속 (SSL 필수)

**방법 A: WAS 서버에서 헬퍼 함수 사용**
```nu
myredis
```

**방법 B: 로컬 터널링**
```powershell
ssh -o ServerAliveInterval=60 -N -L 6380:$REDIS_HOST`:6380 -p $SSH_PORT www@$WEB_PUBLIC_IP
```
*터널링 후 로컬에서 `redis-cli -h 127.0.0.1 -p 6380 -a <KEY> --tls` 접속*

## 5. 접속 및 기능 테스트

### 5.1 접속 테스트 (curl.exe 사용)

PowerShell에서는 `curl` 대신 **`curl.exe`**를 사용해야 옵션이 정상 작동합니다.

```powershell
# 1. Front Door 응답 확인 (HTTPS 헤더 조회)
curl.exe -I "https://$FD_HOST"

# 2. Traffic Manager DNS 조회 (호스트명만 사용!)
nslookup $TM_FQDN

# 3. Application Gateway 직접 접속 테스트 (섹션 1에서 $APPGW_IP 설정됨)
curl.exe -I "http://$APPGW_IP"
```

> **⚠️ 주의:** `nslookup`은 **호스트명**만 입력해야 합니다.  
> ❌ `nslookup https://www.04www.cloud/`  
> ✅ `nslookup www-tm-sojdyc.trafficmanager.net`

## 7. 트러블슈팅

### SSH "Connection timed out"
- **원인:** NSG에서 해당 포트/IP가 차단됨
- **해결:** `az network nsg rule list` 명령어로 NSG 규칙 확인

### SSH "Connection reset by peer"
- **원인:** 대상 서버의 SSH 서비스 문제
- **해결:** Azure Portal → VMSS → Run Command로 `systemctl restart sshd` 실행

### Ping 실패 (100% packet loss)
- **원인:** NSG에서 VNet 내부 트래픽 차단
- **해결:** `allow-vnet-internal` 규칙 추가 필요
